## TL;DR

τ2-bench operationalizes multi-turn agent evaluation across mock, airline, retail, telecom, and banking-knowledge tasks. It supports half-duplex text and full-duplex voice simulations, grades primarily by final environment and communication state, and records interaction metrics that expose latency, interruption, and turn-taking quality.

## Key Claims

- Customer-service agents should be evaluated through simulated interaction with users, tools, databases, and policy constraints.
- Final-state grading allows different correct action sequences to receive credit.
- Reference actions are usually one valid path, not a mandatory trajectory.
- Voice agents need interaction-quality metrics beyond semantic task success.
- Reproducible benchmark use requires pinning the task data, code, domain policy, grader, and simulator configuration together.

## Important Details

- Supported domains at v1.0.1 include mock, airline, retail, telecom, and banking knowledge.
- Text simulation uses half-duplex turn-taking; voice simulation supports full-duplex real-time interaction.
- The final reward is composed from selected reward bases, including database-state and communication criteria.
- A small banking-knowledge subset can require specific actions; most tasks do not require exact reference trajectories.
- Voice metrics include response and yield latency, interruption rate, and selectivity around backchannels, verbal tics, and non-directed speech.
- The repository is large and includes code, task JSON, web assets, audio, and domain data; this note pins the release rather than copying the corpus.

## My Notes

- The implementation details sharpen the original τ-bench lesson: score the state and communication contract, but retain traces to detect unsafe or inefficient paths.
- Voice evaluation is a distinct systems discipline. A semantically correct agent can still be unusable if it interrupts, responds slowly, or mishandles backchannels.
- Version pins matter especially here because changing task data or simulator behavior changes what a leaderboard score means.

## Open Questions

- Which domains have enough task validation to support close model comparisons?
- How stable are rankings across simulator providers and repeated runs?
- Can policy-violation scoring capture harmful intermediate behavior even when the final database state is correct?
